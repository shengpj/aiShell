# 多会话工作区与连接标记

工作区从单个活动 Session 改为多个标签页。每个标签独立持有一条 Connection Profile、终端 WebSocket、远程文件树和 AI 对话；切换标签只改变可见面板，隐藏标签仍保持 SSH 会话和对话状态。关闭标签会卸载该标签的三个面板，终止对应 WebSocket，其他标签不受影响。再次点击已经打开的连接只切换到已有标签，不重复建立同一 Profile 的会话。

连接列表继续负责创建和编辑 Profile，并增加两类本机界面元数据：收藏状态，以及生产、测试、开发环境标签。元数据按 Profile ID 保存在 webview 的 localStorage 中，收藏连接排在列表前面；它们不进入 SSH 凭据、SQLite 主机配置或审计记录，也不影响后端连接权限。

标签标题使用 `用户@地址`，右侧圆点表示该标签已有活动 SSH Session。当前标签的文件浏览、聊天历史和 AI 命令请求都绑定到当前标签的 `sessionId`，因此切换主机不会把文件或对话混到另一台主机上。

**Why**：运维人员经常需要同时观察生产节点、测试节点和跳板机。单一全局 Session 会迫使用户反复断开和重连，也容易把命令发到错误主机；标签页把“当前操作对象”固定在可见上下文里，收藏和环境标签进一步降低选错连接的概率。

**后果**：每个打开的标签都会保留一个 SSH 连接，资源消耗随标签数量增加；当前版本没有跨窗口同步标签，也没有把收藏和环境标签写入后端数据库，清理 webview 本地存储会重置这些界面偏好。AI 回合仍由单个标签独立串行，切换标签不会取消后台标签正在进行的回合。
