# 聊天轮次时间线与会话内删除

右侧 AI 面板原来是一串扁平的消息：用户气泡、命令卡片、回复混在一起，看不出一次问答的边界；命令卡片只有命令和退出码；历史消息不能复制，也不能从对话中移除。本轮（2026-10-29）把它改成按“轮次”组织：每次提问和它引发的命令、回复归为一组，运行中显示处理阶段，悬停用户消息出现时间与复制/删除操作，删除可以把这一轮从界面、`chat_message` 和 ADK 上下文中一起抹掉。

**Why**：用户要的是 Qoder 式的对话体验——看得见 agent 正在思考还是在跑命令；能复制自己说过的话；能删掉一条说错/敏感的消息，而不是只能“新对话”把整段历史作废。删除必须同时作用于模型上下文，否则界面上删了、下一轮模型还在引用，等于没删。

## 设计

### 轮次分组

- 请求体新增 `turn`：前端每轮生成 UUID，随 `/api/chat` 一起提交；后端缺省时自行生成。这样界面在删除或重载前就知道这一轮的标识，不依赖响应回填。
- `chat_message` 的 `turn_id` 早就在表里，本轮把它暴露到 `/api/chat/history`：每条记录带 `turn` 和 `at`（`created_at`）。前端按 `turn` 做连续分组，`user` 行渲染成气泡，其余（`ai` / `command` / `error`）按原顺序排在气泡下方。
- 旧数据（改造前的行）同样有 `turn_id`，因此历史也可以逐轮删除。

### 处理过程展示

- 运行中的状态由“最后一轮的尾部”推断，不需要新增事件：末尾是用户消息 → “正在思考…”；命令 `started` → “正在执行命令…”；命令已结束 → “正在分析执行结果…”；已有回复文本 → “正在回复…”。三点跳动动画 + 文本，`done` 到达即消失。
- 命令卡片增加头部：终端图标 + “执行命令” + 右侧状态（`退出码 0 · 34 ms` / `执行中 · 超时 120s` / `已拒绝：…`），命令本体在下方。
- 已知限制：没有逐条工具调用的可折叠参数区，工具层面只有命令卡片这一种。

### 删除一轮

ADK 事件表 `agent_event` 不记 `turn_id`，只有追加顺序 `seq` 和 `created_at`。删除用时间窗而不是给事件打标：

1. `ChatTranscriptStore.turnWindow(conversation, turn)`：取该轮 `user` 行的 `created_at` 作为起点，取其后第一条 `user` 行的时间作为终点（不含），没有则为开区间。
2. `SqliteAgentSessionService.deleteEventsBetween(session, start, end)`：按 `Instant` 解析每行 `created_at` 后比较再删——`Instant.toString()` 的小数位长短不一（`.001Z` vs `.001234500Z`），字符串字典序比较会错序。
3. `POST /api/chat/delete {session, turn}`：校验终端已连接（409）、该会话没有运行中的轮次（409）、轮次存在（找不到用户行 → 404）；先算窗口，再删 `chat_message`，再删事件，返回 `{turn, messages, events}` 计数。
4. 前端：删除图标让整轮进入选中态（虚线框 + 底部“删除/取消”条），确认后调用接口、从本地列表过滤掉该轮并提示“后续对话不再包含这段内容”。运行中禁用删除按钮，后端同样以 409 兜底。

## 验证

- 新增 `ChatTranscriptStoreTest`：`turn`/`at` 暴露、窗口起点/终点/开区间、只删指定轮、跨会话隔离。
- 新增 `SqliteAgentSessionServiceTest`：区间删除的开闭边界、不影响其它会话。
- 新增 `ChatDeleteEndpointTest`（真实 Spring 上下文 + FakeTerminal + 回显模型）：删掉第 1 轮后，历史里没有该轮文本、ADK 事件里没有该轮文本、下一轮模型收到的用户消息数从 3 降到 2；另有 401/404/409 三个拒绝路径。
- 打包版在真实主机上按原样走了一遍：悬停出现 `时间 + 复制 + 删除`，复制后剪贴板内容与消息一致；删除图标 → 选中态与删除条；点“删除”后界面移除该轮，数据库 `chat_message` 该 `turn_id` 剩 0 行，`agent_event` 中该轮提问与回复文本也剩 0 条，旧轮次不受影响。

**取舍**：时间窗依赖“同一会话的轮次串行执行”（`ChatService` 已用 in-flight 集合保证），也依赖 ADK 事件按追加顺序落在两轮 `user` 行之间；若将来引入并发轮次或后台事件，需要给事件补 `turn_id`。删除不可撤销，也没有多选批量删除；删除只作用于当前会话，不触碰审计日志。
