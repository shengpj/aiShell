# 命令历史与自然语言复用

命令历史复用现有 `audit.jsonl` 及其轮转文件，不新增一套容易分叉的历史存储。后端新增 `/api/commands/history`，只接受当前活动 terminal Session，支持按命令或工作目录关键词过滤，最多返回最近 500 条；记录包含发起者、命令、时间、工作目录、退出码、状态和受限后的输出。

终端顶栏的“历史”面板显示当前 Session 的用户命令和 AI 命令。每条记录支持复制、确认后再次执行，以及“发送给 AI”。再次执行直接写入当前 PTY 并回到现有 shell hook，因此仍会被用户命令审计记录；它不伪装成 AI 命令，也不绕过终端当前的输入接管状态。发送给 AI 会把命令、退出码和输出组成一条待发送草稿，用户仍需检查和提交，AI 执行继续经过执行策略、deny-list、超时和审批流程。

历史查询使用 `chat` ticket，并验证 Session 仍处于活动状态；不能通过一个 Session 查询其他 Session 的记录。搜索只做服务端关键词过滤，复杂的自然语言意图交给 AI 分析，避免在本地复制一套命令语义解析器。

**Why**：运维工作中大量操作是重复的，用户需要快速找到“刚才失败的命令”“在 `/var/log` 下执行过的命令”，并把上下文交给 AI 解释。复用审计日志可以同时保留用户与 AI 的来源、退出码和结果，且不改变既有审计事实来源。

**后果**：历史范围受审计轮转文件限制，超过保留数量的记录不会出现在面板中；当前版本只按活动 Session 查询，重连后 Session ID 改变，旧 Session 的命令不能直接从新连接面板查询。再次执行是明确的用户动作，仍需要用户承担目标主机和命令风险。
