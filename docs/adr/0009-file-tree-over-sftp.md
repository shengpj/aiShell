# 文件树复用终端 Session 的只读 SFTP

文件浏览不新建 SSH 连接：`TerminalBridge` 在认证成功后把 JSch `Session` 暴露给 `TerminalSessions.findSshSession`，`FileService` 每次请求在这条 Session 上开一个 `sftp` 通道（`connect(10_000)`，`finally` 里断开），列表与预览都在通道内完成。**Why**：ADR 0003 已经规定终端与文件浏览共用同一个 Session（见 GLOSSARY 的 Session 定义），复用连接意味着指纹确认、known_hosts、密码/私钥口令与连接配置只有一套；第二个 SSH 连接会让“连接”与“文件”对同一条凭据要求两次认证，也会和目标机的 MaxSessions 打架。

接口：`GET /api/files?session=<id>&path=.` 返回 `{path, entries, truncated}`，`GET /api/files/preview?session=<id>&path=<abs>` 返回 `{path, kind, size, mime, text, data, truncated}`；两者都要求 ADR 0006 的 ticket，用途名 `files`（`/api/files*`），bearer 仍适用于所有 `/api/**`。`session` 是终端 `opened` 帧里发给 webview 的 id；找不到活动会话时返回 409 “terminal session is not connected”，终端断开后前端不需要额外清理即可拿到 409。**Why**：webview 只持有会话 id，不持有任何 SSH 凭据，文件能力与终端能力绑在同一条会话上。

列举语义：`path` 缺省为 `.`（登录用户的 home），先用 `realpath` 归一化再 `ls`，跳过 `.` 与 `..`；目录在前、其余按名字大小写不敏感排序；每层最多 2000 条，超出时 `truncated=true`，前端提示“目录条目过多”。条目类型只有 `dir` / `link` / `file`，符号链接按链接本身呈现、不做跟随。每个条目还带 `permissions`（`SftpATTRS.getPermissionsString()`，如 `drwxr-xr-x`）、`owner` 与 `group`：优先从 `LsEntry.getLongname()` 的空白分隔字段取第 3、4 项（OpenSSH `sftp-server` 会把属主/属组名字放进 longname），字段不足时退回 `getUId()/getGId()` 的数字。**Why**：懒加载按目录取，不做全树扫描，深目录与巨大目录都不会把内存或首屏拖垮；longname 解析不需要额外 `exec` 或读 `/etc/passwd`，拿到的是 `ls -l` 同款权限串，前端可以直接按列展示。

预览语义（只读、有上限）：先 `stat`，目录或非普通文件返回 400；按扩展名识别 png/jpg/jpeg/gif/webp/bmp，超过 4 MB 返回 `kind=too-large`（不带内容），否则读满 4 MB 以内并 base64 成 `image`；其余文件最多读 256 KB + 1 字节判断截断，含 NUL 或严格 UTF-8 解码失败（截断读取允许丢掉末尾最多 3 个字节）即判为 `binary`，否则返回 `text` 与 `truncated`。`SSH_FX_NO_SUCH_FILE` → 404，`SSH_FX_PERMISSION_DENIED` → 403，其余 SFTP 错误与开通道失败 → 502。**Why**：桌面端内存和 JSON 体积都要可控；扩展名判断图片比嗅探内容简单可靠，未知扩展名的二进制会落到 `binary` 分支而不是被当作文本塞进 `<pre>`。

前端 `FileTreePane` 以 `sessionId` 为唯一输入，分左右两栏：左侧 148 px 目录树从 `/` 开始，单击目录名即切换右侧内容到该目录（展开链自动补齐；首次展开才 `list` 该目录并缓存其子目录，展开中的目录显示“加载中…”），单击行首的 `▸`/`▾` 只展开/收起、不切换右侧内容；右侧是当前目录的文件表格，工具栏有上一级、面包屑（根 `/` + 各段，点击任意一段跳转）、截断提示，表格列为 名称/大小/类型/修改时间/权限/用户·用户组，目录排在最前，点击目录名进入该目录、点击文件名打开预览。名称前统一有类型图标（`FileIcon`，内联 SVG，不引入图标库）：目录用闭合/展开两种文件夹图标（树中随展开状态切换，琥珀色），文件按扩展名归类为链接、图片、压缩包、代码（`</>`）、脚本（终端框）、配置（滑杆，含 `.bashrc` 这类点文件）、文本（带横线的文档）与通用文件，各自固定配色，未知扩展名回落到通用文件图标。树中展开链随导航自动补齐（进入 `/etc/ssh` 会展开 `/etc`），当前目录在树里高亮；会话变化（连接或断开）时整体重置并重新列 `/`；刷新按钮清空树缓存重列当前目录；竞态用递增请求号丢弃过期响应。预览覆盖层只在文件面板内部（`position: absolute`），文本左对齐，`Escape` 或“关闭”收起；图片用 `data:` URL，二进制与超限只显示说明。表格用 `table-layout: fixed`、名称列吸收剩余宽度，固定列合计约 390 px，1280 宽窗口下六列无需横向滚动、长文件名省略号截断。v1 不做右键菜单、上传、下载、删除与在线编辑，面板标题右侧固定显示“只读”徽标。**Why**：左右分栏让“在哪”和“有什么”同时可见，树只负责导航、表格负责细节，符合本地文件管理器的心智模型；懒加载加缓存让深目录逐层展开只付一次成本；把副作用限制在只读，文件树不会成为第二条绕过审计的写路径；边界也要写在界面上，用户不必读 ADR 才知道为什么不能改文件。

**验证状态**：后端 117 个测试全绿（1 个 live spike 跳过），其中 `FileServiceSftpTest` 9 例（MINA `sshd-sftp` + `VirtualFileSystemFactory`：排序与隐藏文件、嵌套路径、UTF-8 文本、300 KB 截断、图片 base64、4 MB 超限、NUL 二进制、权限与属主、目录 400 与缺失 404），`FileEndpointTest` 3 例（无凭据 401、`files` ticket 一次性且会话缺失 409、终端用途 ticket 被拒 401）。真实主机 `121.41.177.215` 上早期经 Chrome + `__TAURI_INTERNALS__` 桩走通单栏树：私钥配置登录后文件树列出 `/root`；终端里建 `aishell-dir/sub/deep.txt`、文本、1×1 PNG 与 NUL 文件后刷新可见；逐层展开 `aishell-dir` → `sub`（缩进 8/22/36px）预览 `deep\n`；文本预览内容与 20 B 大小一致；PNG 以 `data:image/png;base64,...` 渲染出 1×1；NUL 文件显示“二进制文件，暂不支持预览。”；列出后删掉的文件再点预览得到 404 “path not found: /root/aishell-gone.txt”；点“断开”后文件树回到“连接终端后显示远程目录。”并关闭预览；测试文件已删除。原生窗口内的链路后来在打包版上补验：鼠标点击 `.cache` 节点后展开出 `pip` 子目录（ADR 0013）。**2026-10-29 双栏改版复验（打包版 + UIA）**：连接 `dev` 后左侧树从 `/` 展开为 `boot`…`var`；当时单击树中 `root` 只展开其子目录、右侧仍停在 `/`（这是旧语义，见段末修正）；右表六列（名称/大小/类型/修改时间/权限/用户·用户组）在 1280 宽窗口下完整可见，`boot`、`lost+found` 等目录权限为 `drwxr-xr-x`、属主 `root/root`，文件显示大小与 `-rw-r--r--`；点表格里的 `boot` 进入 `/boot`（面包屑 `↑ / boot`，树中 `boot` 高亮并展开 `efi/grub/grub2`）；回 `/` 再进 `etc`，点 `hostname` 打开预览（`/etc/hostname`、24 B、文本左对齐），点“关闭”收起；预览期间覆盖层只遮住文件面板，终端与聊天不受影响。**同日修正（用户反馈“点左侧目录右侧没变化”）**：树行的 `onClick` 改为 `navigate`，`▸/▾` 自带 `stopPropagation` 后走 `toggleTreeDir`，并给光标加了 `cursor: pointer`/hover 反馈；换目录时右表滚回顶部。打包版复验：点击树中 `etc` → 右侧切到 `/etc`（面包屑 `↑ / etc`，`etc` 高亮并展开）、再点其子目录 `alternatives` → 右侧继续切到 `/etc/alternatives`，即“点名字=进目录”。**图标（同日）**：`FileIcon.tsx` 提供 10 种内联 SVG 图标，按扩展名归类（图片 `png/jpg/gif/svg…`、压缩包 `zip/tar/gz…`、脚本 `sh/zsh/ps1…`、代码 `js/ts/java/py/go…`、配置 `conf/yml/json/service…` 与点文件、文本 `txt/md/log/csv…`），无扩展名与未知类型回落到通用文件图标；表格名称列改为 `flex`（图标 + `.file-name-text`），长文件名仍在文本节点上省略。先在 1:1 的静态页里比对两种尺寸的图标造型，再在打包版确认：`/` 与 `/etc` 列表、树中 `/`→`etc` 的文件夹图标、面包屑 `↑ / etc` 与 `/opt/tomato/logs` 下日志文件的通用文件图标均正常，图标列宽未挤占名称列。

**已知取舍**：不监听远程变更，目录内容靠刷新按钮与重新展开更新；符号链接不跟随；UTF-16 等非 UTF-8 文本按二进制处理；图片上限 4 MB、文本上限 256 KB 为常量而非可配置；表头不排序、无右键菜单，排序列固定为“目录在前 + 名称”；窗口变窄时名称列先被压缩、其余五列保持可见（完整路径在 tooltip 里）；`findSshSession` 只按会话 id 查内存中的活动连接，后端重启后终端与文件树一起失效。
