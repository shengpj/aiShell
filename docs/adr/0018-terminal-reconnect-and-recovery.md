# 连接与终端中断恢复

终端 WebSocket 断开后，前端保留最近一次连接配置和终端内容，不把异常断开误认为用户主动断开。连接建立后发生网络中断时，按 1、2、4、8、15 秒退避自动重连，最多尝试 5 次；重连成功后继续复用同一个 Host 的对话 key，并重新获取一次性 terminal ticket。自动重连停止后，用户可以点击“重新连接”再次开始一轮新的尝试。

用户点击“断开”、切换连接或关闭页面时标记为主动操作，清理重连定时器，不自动恢复。SSH 认证失败、主机指纹/密码确认失败和服务端明确返回的 `error` 也不自动循环，界面保留具体错误原因；正常 shell EOF 同样需要用户手动重新连接。

连接状态在终端顶栏和底部消息区表达：连接中、已连接、连接已中断、自动重连倒计时和重连停止。连接中断期间清理 `sessionId`，因此 AI、文件浏览和当前连接绿点都会立即停止使用已经失效的 SSH Session，避免把新请求发送到旧会话。

**Why**：网络抖动、后端重启和 SSH 空闲断链是运维终端的常见失败方式。保留上下文并自动恢复可以减少重复填写连接配置；主动断开和认证错误不自动重试，则避免用户明确停止后又被重新连接，或因凭据错误形成重试循环。

**后果**：自动重连只恢复终端连接，不重复执行中断前的命令，也不自动重放未完成的 AI 回合。重连后需要用户重新确认主机指纹或输入密码时，提示仍在终端内完成；对话历史按 Host 持久化，重新建立的 Session 可以继续查看同一会话历史。
