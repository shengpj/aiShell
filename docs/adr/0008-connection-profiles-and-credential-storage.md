# 连接配置存本机 SQLite，凭据用 AES-GCM 加密

Host 与 Connection Profile 直接落本机 SQLite（`ai-shell.data.dir/ai-shell.db`），用 `org.xerial:sqlite-jdbc` + `DriverManager`，不引 `spring-jdbc`（Boot 4 的 `starter-jdbc` 与 Spring 7 `spring-jdbc` 在离线仓库里没有，ADR 0004 的离线约束仍然有效）。每次操作开一条连接，开库时 `PRAGMA journal_mode=WAL` 与 `busy_timeout=3000`；`host` 与 `connection_profile` 两张表都用 `deleted_at` 软删除，删 Host 在同一事务里软删它的 Profile，审计记录提到的主机与配置因此永远可解析。**Why**：单用户桌面工具，数据量以十计，需要的是零外部依赖与随时可备份的单文件，而不是连接池或迁移框架；软删除是 Q28 的审计要求。

凭据（密码、私钥口令）加密后才入库：AES-256-GCM（`AES/GCM/NoPadding`，12 字节 IV，128 位 tag），存成 `v1:` + base64(iv||ciphertext)。主密钥是 32 字节随机数，由 Rust 首次启动时生成并写进 Windows 凭据管理器（target `AI Shell/master-key`，user `ai-shell`，generic 类型，本机持久化），之后每次启动读出、经环境变量 `AI_SHELL_MASTER_KEY` 交给 sidecar，与 ADR 0005 的令牌同路，Java 侧只从配置读、不落盘。**Why**：SQLite 文件本身不加密，密码明文入库就等于明文落盘；主密钥交给操作系统凭据库，避免自己再发明一个口令或把密钥平铺在文件里。Rust 端用两个 UUIDv4 拼出 32 字节，省掉一个 RNG 依赖。非 Windows 平台拿不到凭据库时不回退到弱密钥，后端保持“未配置加密”状态：建配置照常、带 secret 的写入与解析返回 503。

凭据永不回传 webview：REST 返回 `hasSecret` 布尔值而不返回密文或明文；终端连接只发 `{"type":"open","profile":"<id>"}`，由后端 `HostService.resolve` 解出地址、端口、用户、私钥路径与明文口令。有保存口令时 `TerminalBridge` 不弹提示，直接用于认证；如果服务器走的是 keyboard-interactive 而不是 password，`promptKeyboardInteractive` 会对首个不带回显且提示含 password/passphrase 的问题给出保存口令，其余问题仍然写进终端让用户回答。没有保存口令时行为不变：提示仍由后端写进终端字节流，用户在终端里输入（Q26/Q21）。更新语义区分“保留”与“清除”：`secret` 字段缺省（null）表示保留旧值，空字符串表示清除，非空表示替换并重新加密。

接口与前端：`/api/hosts`、`/api/hosts/{id}/profiles`、`/api/profiles/{id}` 走 ADR 0006 的 ticket，用途名 `hosts`（`/api/hosts*` 与 `/api/profiles*` 都映射到它），bearer 仍可用于所有 `/api/**`。错误响应统一由 `ApiExceptionHandler` 转成 RFC 7807 ProblemDetail，`detail` 里带校验原因，前端直接展示。左侧栏内联表单新建/编辑 Host 与 Profile，删除用 `window.confirm` 二次确认并提示“审计记录会保留”；配置行本身是连接按钮。

**UI 流程（2026-10-28 调整）**：左侧“连接”面板右上角的 + 打开“新建连接”表单，字段为名称、地址、端口、用户名、私钥文件与密码。私钥文件用“选择文件”按钮调 `@tauri-apps/plugin-dialog` 的原生打开对话框（Rust 侧 `tauri-plugin-dialog`，capability 增加 `dialog:default`），选中后回填只读路径并可“清除”；选了私钥时密码字段改称“私钥口令”。提交按钮就是“连接”：先落库 Host/Profile（同地址端口复用已有 Host，否则新建），再用返回的 profile id 立即发起终端连接，所以表单只出现一次、信息随连接保存。配置行的“编辑”打开同一个表单（地址/端口锁定，只改用户名与凭据）；主机地址仍由主机行的“编辑”修改。终端顶栏不再有主机/端口/用户名/私钥输入框，只保留连接与审计徽标和“断开”，未连接时中间提示“在左侧选择已有连接，或点击 + 新建连接”。**Why**：连接参数是持久配置，不该每次重输，也不该有两个入口；凭据仍只回传 `hasSecret`，文件选择只拿到路径、不读取内容。

**删除确认**：`window.confirm` 在 Tauri 的 WebView2 里不会阻塞（调用立即返回、等同默认确认），旧实现因此会出现“没点确认就删了”。改为 `@tauri-apps/plugin-dialog` 的 `confirm()`：原生模态对话框，权限必须同时给 `dialog:default` 与 `dialog:allow-confirm`（`dialog:default` 只含 message/save/open）；对话框调用失败时按“拒绝删除”处理，宁可删不掉也不能无确认删除。原生窗口复验：点配置行“删除”弹出“删除连接 / 删除连接配置 TestHost？”，点“取消”两次均保留配置；不进行任何操作时对话框会一直等待（13 秒观测）。

**启动加载**：冷启动时后端需要约 3–4 秒，左侧先显示“正在加载连接…”，加载成功后才有“暂无连接”的空态。轮询在三种情况下都重试：`backend_info` 仍是 `starting`（1 秒）、调用本身抛异常（1 秒）、列表请求失败（1.5 秒），直到成功或后端 `failed`。此前只在 `starting` 时重试，任何一次启动期异常都会让轮询永久停止，表现为“已保存的连接不显示，随便保存一个之后才全部出现”。原生窗口测量：0.3 秒空窗口 → 3.4 秒“正在加载连接…” → 7.4 秒列出已保存连接并显示“后端已连接”。

**S4 前置阶段验证状态**：后端 62 个测试全绿（2 个 live spike 跳过），其中 `SecretCipherTest` 5 例、`HostServiceTest` 7 例、`HostEndpointTest` 5 例、`TerminalWebSocketTest` 新增保存口令登录 1 例（MINA 的 keyboard-interactive 提示由保存口令应答，不出现密码提示）。Rust 侧 `master_key_survives_a_second_read` 标为 ignored，手动执行过一次，确认凭据管理器里的密钥可重复读出且为 32 字节。UI 验证当时在真实 Chrome + `__TAURI_INTERNALS__.invoke` 桩下进行（原生窗口点击链路当时尚未打通，后来在 ADR 0013 补验）：经界面建 Host、建私钥配置后点击配置，后端按 profile 解析并以 `C:\Users\Administrator\fanqie.pem` 登录 `121.41.177.215`，首次指纹确认在终端内输入 `yes` 后收到 `opened` 与 shell 提示符，粘贴 `echo UI-PROFILE-OK` 回显输出正确；另建一个带口令的密码配置，列表显示“密码 · 已保存”，库内只看到 `v1:` 密文、搜不到明文；重启后端后主机与配置仍在（含 `hasSecret`），重连不再出现指纹提示（known_hosts 已持久化）；界面删除配置与主机后列表清空，数据库中两行仍在（仅写 `deleted_at`）。原生窗口内的链路后来在打包版上补验：连接表单的鼠标点击与真实键入、指纹确认、终端键盘输入均走真实输入（ADR 0013），本段的 Chrome 结论仍然有效。2026-10-28 的原生窗口复验覆盖新的连接入口：点 + 打开“新建连接”，填名称/地址/用户名，用“选择文件”在原生对话框里选 `fanqie.pem`（路径回填、密码标签变为“私钥口令”），点“连接”后列表出现 `TestHost root · 私钥`，终端进入 `审计就绪 · bash` 并列出 `/root`；重启应用后连接仍在列表，终端顶栏没有输入框；点击该配置行可再次连接。

**删除粒度与表单默认值（2026-10-29 修正）**：新建连接会按 address:port 复用已有 Host，因此一个主机下常有多条连接，而旧实现的主机行“删除”会级联软删该主机下所有 Profile。实际数据印证了这一点：2026-10-29T01:54:56Z 的一次删除把 TestHost 及其两个 Profile 写入了同一个 `deleted_at`，用户看到“删其中一个，全部消失”。修正后的语义是“删除即删连接”：删除按钮只出现在 Profile 行（`removeProfile`），主机行的“删除空主机”仅在 `host.profiles.length === 0` 时渲染，`removeHost` 自身也拒绝删除仍有连接的主机；确认文案分别写明“该主机下的其他连接不受影响”与“该主机下已无连接”。后端 `deleteHost` 的级联与软删保持不变（审计记录仍可解析），但不允许从界面触达有连接的主机。同时新建连接与主机编辑表单不再有任何示例默认值：名称/地址/端口/用户名初值均为空，移除 `121.41.177.215`、`root`、“例如 生产 Web”等占位；端口留空按 22 保存，并在标签中提示“默认 22”。**Why**：占位示例会被用户当成已填的默认值，主机级删除则把“删一条连接”放大成“删全部”。

**2026-10-29 原生验证**：在 Tauri dev 窗口上通过 WebView2 远程调试（`--remote-debugging-port`，仅验证参数，不进发布配置）驱动真实 DOM。新建连接表单六个输入值为空且无 `121.41.177.215`；同一主机（127.0.0.1:1）建立 verify1/verify2 两条连接后，主机行只有 `+` 与“编辑”，没有“删除”；删除 verify2 后 verify1 与主机保留；删除 verify1 后主机变空并出现“删除空主机”，确认后列表回到“暂无连接”；三处原生确认框（删除连接 ×2、删除主机 ×1）均由真实鼠标点击“删除”完成，取消路径沿用既有验证。

**空主机随之退休（2026-10-29）**：删除最后一条连接后，界面上会留下一个 `profiles` 为空的主机分组，并渲染“尚无连接配置”，与“连接列表里明明有数据”的直觉冲突。修正分两层：后端 `HostStore.deleteProfile` 改为事务——软删 Profile、统计该主机剩余活动 Profile，数量为 0 时把 Host 一并软删（审计记录仍可解析）；前端只渲染 `profiles.length > 0` 的主机（`visibleHosts`），空态文案“暂无连接”也按可见主机判断，因此历史库里已存在的空主机不会再显示。主机行上原本的“删除空主机”按钮随之删除（无法再从界面触达空主机），`removeHost`/`deleteHost` 前端封装不再被使用，只保留后端 `DELETE /api/hosts/{id}` 及其级联语义。删除最后一条连接时确认文案改为“这是该主机下的最后一个连接，主机记录会一并移除，审计记录保留”，其余连接仍是“该主机下的其他连接不受影响”。**Why**：Host 只是连接的归组，没有任何连接后它既不能点击也不能删除，是纯粹的噪声；让数据库与界面都收敛到“没有连接就没有主机”，比再加一个“删除空主机”的按钮更少歧义。**验证**：`HostServiceTest` 新增“删最后一条连接使主机退休”“两条连接删一条保留主机”，`HostEndpointTest` 新增同名 REST 用例；后端 115 个测试 0 失败（1 个 live 测试跳过）。打包版对用户真实库（仅有一个 `web / 121.41.177.215:22` 空主机）启动，左侧直接显示“暂无连接”，不再出现空分组与“尚无连接配置”。

**扁平连接列表与连接状态（2026-10-29）**：主机分组头（`web` + 地址）与组内连接行（`dev` + `root · 私钥`）视觉上都是“一条连接”，用户因此把一条连接看成两条，且两行的副标题一个显示 IP、一个显示用户名与认证方式。改为一条连接一行：标题是连接名，副标题统一为 `用户名@地址:端口`（如 `root@121.41.177.215:22`），认证方式移到整行的 `title` 提示里。列表顺序由后端决定并保证“新建的在上”：`HostStore.listHosts` 按该主机最新活动连接的 `created_at` 倒序（同地址端口复用主机时，旧主机也会带着新连接浮到顶部），`listProfiles` 按 `created_at` 倒序。主机分组头与主机级“编辑地址”入口随之消失；地址与端口改为在连接的编辑表单里修改（同一主机下有多条连接时提示“共用地址与端口，修改会一起生效”）。当前终端会话的连接在行右上角显示绿点：`App` 用 `sessionId && connection.profileId` 推出 `connectedProfileId` 传给左栏，`opened` 后出现、`断开`/`closed`/`error` 后消失，悬停时淡出以露出编辑/删除按钮。**Why**：连接是用户操作的单位，主机只是实现复用（同一 address:port 多个用户名/凭据）的内部概念，把它画成一层可见的“假连接”只会制造歧义；绿点则让“终端已连接的是哪一条”一眼可见，不用回看终端徽标。**验证**：`HostServiceTest` 新增排序用例（新主机在前，旧主机新增连接后重新置顶），后端 116 个测试 0 失败（1 例 live 跳过）；打包版对真实库显示单行 `dev / root@121.41.177.215:22`，UIA `InvokePattern` 点击后终端进入 `审计就绪 · bash` 且该行右上角出现绿点，点“断开”后绿点消失。
