# AI 命令执行策略

AI 回合支持三种执行策略，由前端随每轮请求传给后端，并由后端的 `RunCommandTool` 强制执行：

- `auto`：保持当前行为，模型通过现有 deny-list、超时和会话独占后直接执行命令。
- `confirm`：命令写入 PTY 前暂停，通过 SSE 发出一次性 approval token；用户批准后才执行，拒绝、停止或超时都会生成拒绝审计记录。
- `explain`：不允许写入 PTY，工具返回拒绝原因，让模型解释命令和建议，而不是执行它。

确认状态只保存在后端内存中，不进入 SQLite。待确认事件不写入聊天历史，批准或拒绝后的最终命令事件照常写入历史与 `audit.jsonl`。停止接口会同时取消 PTY 中的命令和等待中的审批。

**Why**：AI 全自动执行适合熟练用户，但首次使用、生产主机和高风险排查需要一个渐进的控制方式。确认必须发生在后端工具真正写 PTY 之前，前端开关不能成为执行控制本身。

**后果**：审批 token 在 sidecar 重启或 SSE 断开后失效；策略偏好当前保存在 webview 的 localStorage 中，后端配置 `ai-shell.ai.execution-policy` 作为缺省值，默认保持 `auto` 以兼容已有用户。
