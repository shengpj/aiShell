# 受控文件传输与文本编辑

文件面板从只读浏览扩展为两类明确动作：下载和编辑已有文本文件。两类动作都必须使用当前活动 SSH Session，并由后端通过 `files` ticket 校验；下载上限为 4 MiB，文本编辑上限为 256 KiB。

编辑只允许普通文件，不允许目录、链接或新建路径。保存请求携带预览时的远程修改时间，后端发现版本变化就返回冲突，要求用户重新加载，避免覆盖他人刚写入的内容。写入先上传到同目录临时文件，再替换目标，并尽量保留原文件权限。保存和下载都会写入 `audit.jsonl`，但文件事件不伪装成 shell 命令。

前端保存前使用确认对话框，编辑器只是用户明确操作的入口；AI 没有新的文件写工具，因此不会绕过确认、版本检查或审计链路修改文件。

**Why**：只读浏览无法完成小范围配置修复和结果留存，但直接提供任意远程写入会扩大风险。大小、类型、版本和审计边界让常用的文本修复保持可控。

**后果**：当前版本不支持新建文件、删除、重命名、目录上传、批量操作或 AI 直接写文件；超过大小上限或被其他进程修改的文件需要通过终端或外部流程处理。
